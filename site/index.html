Feedback that does not wait in line

Shipping an interface is a hundred small corrections. Each one costs you a screenshot, a paste and a paragraph about which button you mean. Then you watch the terminal to see if the agent understood.

jrabbit takes those steps out. You point, write one line and send. The fix lands on the page in front of you, usually before you have found the next thing to change.

How it works

  1. Open

    Tell your agent to open a jrabbit review. Your app opens with the jrabbit bar on top. Your code is not touched.

  2. Point

    Press P, click the element, write what should change and press ⌘↵. That sends it. Add several first if you want them fixed together.

  3. Fix

    Your agent gets your comment with a screenshot and the exact file and line. It edits the code without asking you to confirm.

  4. Check

    The page updates and the pin shows before, after and how long the fix took. Approve it, or reopen it with a note.

Send it once

Other tools hand your note to the agent and hope it is listening. jrabbit keeps your agent on the review. It waits for your pins, takes each one as you send it, and goes back to waiting when the fix is in.

  • In Claude Code, your agent cannot end its turn while your review is open.
  • In Codex and Cursor it waits in a loop, and picks up whatever you sent while it was busy.
  • Send five pins together and it fixes them in one pass.
  • It stops when you press Done, close the tab, or leave the review alone for half an hour.

Each pin also carries its screenshot. File and line work for React apps on Next.js and Vite. Anywhere else, your agent gets the text, classes and test ids to search for.

Say it twice and it becomes a rule

When you repeat a correction, your agent proposes a rule. Nothing applies until you approve it. Approved rules are Markdown files in .jrabbit/rules/, committed with your repo, and your agent reads them before it starts.

Set up in one line

npx jrabbit init
  • It finds Claude Code, Codex and Cursor on your machine and sets up each one. Or paste the setup prompt and your agent does it for you.
  • There is no account and no API key.
  • Pins, screenshots and rules are files in .jrabbit/ inside your project. Nothing leaves your machine.
  • Pages behind a login work, because the review shares your dev server's cookies.
  • MIT licensed, with the code on GitHub.

Questions

Rather install it by hand? 
npx jrabbit init

Run it from your project root. It sets up every agent it finds.

Does jrabbit change my code?

No. It serves your app through a local proxy and adds the overlay there. Your agent makes the edits, the same way it does today.

Do I have to tell my agent to check for feedback?

No. While the review is open your agent is waiting for your pins, and a sent pin is the request: it changes the code without asking. If you send something while it is busy, it takes it next.

How do I stop it?

Press Done in the Pins panel, close the review tab, or tell your agent you are done. Left alone for 30 minutes, it stops by itself.

Which agents does it work with?

Claude Code, Codex, Cursor, and any client that runs MCP servers over stdio.

Which frameworks?

Any web app on a local dev server gets pins with a screenshot, selector and styles. File and line need React on Next.js or Vite. Adapters for Vue, Svelte and Astro are welcome contributions.

Where do my screenshots go?

To the .jrabbit/ folder in your project, and to your agent when it reads a pin. jrabbit itself sends nothing anywhere.

What does it cost?

Nothing while you work alone: that part is free and MIT licensed, with no limits. Paid plans start when you bring a client into the review, from $9 per project. See pricing.
