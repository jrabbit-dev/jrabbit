How it works

  1. Open

    Ask your agent to open a review of localhost:3000. jrabbit serves your app with the overlay on top and never edits your code.

  2. Point

    Press P, click an element and write the change. Add as many pins as you need, then press Send.

  3. Fix

    Your agent receives every pin with your comment, a screenshot, the selector and the file and line, and edits the code.

  4. Check

    Each pin comes back with a before and after shot. Approve it, or reopen it with a note.

Each pin also carries its screenshot. File and line work for React apps on Next.js and Vite. Anywhere else, your agent gets the text, classes and test ids to search for.

Say it twice and it becomes a rule

When you repeat a correction, your agent proposes a rule. Nothing applies until you approve it. Approved rules are Markdown files in .jrabbit/rules/, committed with your repo, and your agent reads them before it starts.

Runs on your machine

  • One line to install. There is no account or API key.
  • Pins, screenshots and rules are files in .jrabbit/ inside your project.
  • Pages behind a login work, because the review shares your dev server's cookies.
  • MIT licensed, with the code on GitHub.

Questions

Rather install it by hand? 
claude mcp add jrabbit -- npx -y jrabbit

Run it from your project root.

Does jrabbit change my code?

No. It serves your app through a local proxy and adds the overlay there. Your agent makes the edits, the same way it does today.

Which agents does it work with?

Claude Code, Codex, Cursor, and any client that runs MCP servers over stdio.

Which frameworks?

Any web app on a local dev server gets pins with a screenshot, selector and styles. File and line need React on Next.js or Vite. Adapters for Vue, Svelte and Astro are welcome contributions.

Where do my screenshots go?

To the .jrabbit/ folder in your project, and to your agent when it reads a pin. jrabbit itself sends nothing anywhere.

What does it cost?

Nothing. jrabbit is free and MIT licensed.
